# Lista do przeczytania — 2026-11-26
Temat: ai, llm, agent.

## 1. [MCP servers can now ship skills, run tasks, and more with Claude](https://claude.com/resources/articles/skills-over-mcp-tasks-and-more)
Anthropic ogłosił 24 listopada, że serwery MCP mogą udostępniać w Claude nie tylko narzędzia, ale także gotowe „skills” (Skills over MCP, public beta). Mechanizmy Tasks (długotrwałe operacje wykonywane w tle i zwracające wynik później) oraz Elicitation (serwer może dopytać użytkownika o brakujące dane) stały się ogólnodostępne w Claude i Claude Code dla planów Pro/Max/Ultra, a Team/Enterprise dostają je stopniowo. Wkrótce dojdzie eksperymentalne rozszerzenie File Uploads.
**Dlaczego warto:** To wyraźne przejście MCP od bezstanowych wywołań narzędzi do stanowych, długotrwałych workflowów agentowych — ważne dla każdego, kto buduje własne serwery MCP lub integracje z agentami.

## 2. [Did the user ask for this? Securing AI agents against intent hijacking with Semantic governance policies](https://developers.googleblog.com/did-the-user-ask-for-this-securing-ai-agents-against-intent-hijacking-with-semantic-governance-policies/)
Google opisuje Semantic governance policies (preview w Gemini Enterprise Agent Platform) — bramkę, w której model-sędzia sprawdza każde proponowane wywołanie narzędzia pod kątem tego, czy użytkownik faktycznie o nie prosił, oraz zgodności z regułami zapisanymi językiem naturalnym. Wyniki narzędzi, pliki i wiadomości traktowane są jako dane, nie instrukcje. W benchmarku AgentDojo skuteczność ataków typu prompt injection spadła z 48,7% do 0,9% przy spadku użyteczności na zadaniach nieszkodliwych średnio o ok. 2,6 p.p.
**Dlaczego warto:** Konkretny, zmierzony wzorzec obrony przed przejęciem intencji agenta — choć to benchmark samego dostawcy, a sędzia-LLM też czyta potencjalnie zatrute dane, co warto mieć z tyłu głowy.

## 3. [AI Agents Have A Permissions Creep Problem. Security Fundamentals Could Fix It](https://www.forbes.com/sites/timkeary/2026/11/25/ai-agents-have-a-permission-creep-problem-security-basics-can-fix-it/)
Tekst Forbesa (25.11) omawia badania Token Security, z których wynika, że agenci AI z czasem gromadzą coraz szersze uprawnienia: wśród tych samych użytkowników porównanych w odstępie ośmiu tygodni odsetek osób, których agenci uruchamiali wrażliwe narzędzia, wzrósł z 38% do 67%, a liczba wywołań narzędzi na osobę wzrosła 2,8-krotnie. Ponad połowa firm ma też osobistych asystentów-agentów podłączonych do służbowych kont. Autor argumentuje, że rozwiązaniem są klasyczne zasady bezpieczeństwa: najmniejsze uprawnienia, inwentaryzacja tożsamości i regularne przeglądy dostępu.
**Dlaczego warto:** Dobrze pokazuje, że ryzyko agentów rośnie po cichu wraz z ich użyciem — i że część problemu da się ograniczyć znanymi od lat praktykami IAM, zanim sięgnie się po nowe narzędzia.

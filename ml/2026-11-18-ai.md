# Lista do przeczytania — 2026-11-18
Temat: ai, llm, agent.

## 1. [Advancing computer-use agents for healthcare teams](https://openai.com/index/advancing-computer-use-for-healthcare-teams/)
16 listopada OpenAI udostępniło agentów typu computer-use dla placówek medycznych przez API, ChatGPT for Healthcare i ChatGPT for Clinicians. Agenci mają przejmować pracę administracyjną, np. formularze, wnioski o zgodę ubezpieczyciela (prior authorization) i pracę w systemach EHR. Organizacja sama ustala, jakie akcje agent może wykonać, może go w każdej chwili zatrzymać i dostaje szczegółowy log do audytu. Gdy dane w dokumentacji są niejednoznaczne, agent zatrzymuje się i czeka na decyzję klinicysty. OpenAI podaje, że lekarze ocenili 99% z 325 sprawdzonych zadań jako bezpieczne. To jednak oceny wyników modelu, a nie zmierzone efekty dla pacjentów. Partnerami wdrożeń są m.in. CVS Health, Cigna, Abridge i Ambience.
**Dlaczego warto:** Agenci obsługujący interfejsy graficzne wchodzą do jednej z najbardziej regulowanych branż. Wzorzec „uprawnienia + zatwierdzanie przez człowieka + log audytowy” będzie prawdopodobnie punktem odniesienia dla agentów w innych sektorach.

## 2. [Building always-on agents](https://claude.com/blog/building-always-on-agents)
Tekst z bloga Claude (William Hu, 13 listopada) o architekturze agentów, którzy działają w tle i nie czekają na wiadomość od użytkownika. Większość czasu taki agent jest bezczynny, a budzi się na zdarzenia, np. webhooki, harmonogramy albo odpowiedź użytkownika. Autor opisuje pięć podstawowych elementów: trwałą skrzynkę zdarzeń z deduplikacją i jednym aktywnym workerem, timery (follow-upy i zadania cykliczne), pamięć trzymaną poza workerem, uprawnienia (poświadczenia za proxy, przegląd ryzykownych akcji, wstrzymanie do decyzji użytkownika) oraz outbox, który dawkuje wiadomości. Radzi też, żeby agent na początku odzywał się rzadko i z czasem zasłużył na uwagę użytkownika.
**Dlaczego warto:** To konkretny, inżynierski opis budowy długo działających agentów. Przydaje się każdemu, kto przechodzi od prostego chatbota do agenta reagującego na zdarzenia i potrzebuje sprawdzonego podziału odpowiedzialności.

## 3. [What's new in Microsoft Agent 365: Ignite 2026](https://techcommunity.microsoft.com/blog/agent-365-blog/whats-new-in-microsoft-agent-365-ignite-2026/4571753)
Na Ignite 2026 (17–20 listopada) Microsoft pokazał rozwój Agent 365, czyli centralnego rejestru i panelu zarządzania agentami w firmie. Według Microsoftu od majowej premiery zarejestrowano w nim ponad 50 mln agentów. Defender i Global Secure Access mają teraz wykrywać lokalnych agentów działających bez zgody firmy (shadow agents), np. Claude Code czy GitHub Copilot CLI, i dodawać ich do rejestru. Ta funkcja jest w wersji preview. Podstawowe statystyki dla wbudowanych agentów Microsoftu są dostępne bez licencji Agent 365, ale zaawansowane zarządzanie agentami firm trzecich nadal jej wymaga.
**Dlaczego warto:** Zarządzanie flotą agentów, w tym tymi uruchamianymi przez pracowników na własną rękę, staje się osobną kategorią produktów. Firmy powinny już teraz planować inwentaryzację i polityki dla agentów.
